## 3. Build the new combined taxa table and derive_taxa()

- [x] 3.1 Define the new `taxa` table in `create_new.sql`: same identity/classification/provenance column shape as `taxa_linnaean` (`original_permid`, `accepted_spelling_permid`, `concept_permid`, `containing_concept_permid`, `classification_path`, `nomenclatural_status_id`, `winning_*_opinion_id`), as independent storage — not a view over the other three tables
- [x] 3.2 Implement lineage grouping in the new `derive_taxa()`: same union-find/topological-sink logic as `derive_linnaean()`, over `name_opinions`, with no rank-based exclusion
- [x] 3.3 Implement concept grouping over `name_opinions`' concept-class edges with no rank-based exclusion, so Linnaean and clade lineages merge into concepts on the same terms
- [x] 3.4 Implement accepted-spelling selection, reusing the same eligibility rules (`never_accepted`, nomen nudum barring, negation) `derive_linnaean()` uses
- [x] 3.5 Implement classification pooling over `assignment_opinions` with no rank-based exclusion, producing a single `containing_concept_permid` per concept from the merged candidate pool (Linnaean-Linnaean, clade-clade, and cross-boundary candidates all compete together) — the rank-cardinality/inversion check is kept but reimplemented against `taxonomy_ranks.height` (NULL-safe) instead of `derive_linnaean()`'s raw `rank_id` comparison, which is only safe there because it never evaluates a candidate touching unranked/unranked clade; this function has no such upstream exclusion to lean on
- [x] 3.6 (superseded by 3.5's height-based rework — see above; "rank-cardinality as a cycle-cut tiebreak" turned out not to exist in the current code at all, see 3.7)
- [x] 3.7 Implement the cycle-cut loop using its own `_dtu_*`-prefixed temp tables. Correction to this task's premise: `derive_linnaean()`'s and `derive_taxa_clades()`'s actual cut order is `evidence ASC, yr ASC NULLS FIRST, is_senior ASC, opinion_id ASC` — there is no separate rank-cardinality tier inside the cut loop in either; rank-cardinality is the upstream exclusion filter (task 3.5), not a cut-tiebreak. The new function reuses that exact order unchanged.
  - **Major correction found during real-data testing**: `derive_linnaean()`'s/`derive_taxa_clades()`'s cycle-member detection (walk from every non-root node up to depth 10000, checking for a self-revisit) is only cheap when a broken cycle is small AND deep in the tree. Against real `pg_play` data, dropping the rank exclusions surfaced a genuine 3-concept cycle among basal unranked clades (Eukarya/Proepitheliozoa/Euradiculata) sitting at the root of the entire eukaryote subtree — ~283,038 of 356,933 concepts (79%) are its descendants, so the per-node walk was performing on the order of 283K × 10000 row explorations and never finished in practical time. Replaced the cycle-member detection with iterative peeling (Kahn's algorithm in reverse — repeatedly delete any node whose own parent isn't itself still present; survivors = cycle(s) + everything downstream, O(V) per round) plus a single bounded walk from one survivor to isolate that one cycle's actual members, matching the approach already prototyped in `migration_exploration/testing/find-containment-cycle.js` for this exact problem. Verified end-to-end against the full real dataset: `derive_taxa(NULL)` now completes in ~12 minutes (53 cut iterations needed to fully resolve the merged graph — see 3.11), versus never finishing before.
- [x] 3.8 Wire cycle-cut logging to the shared `cycle_cuts` table with `source = 'taxa'` (also added `'taxa'` to the `cycle_cuts.source` CHECK constraint, alongside the new `'taxa_linnaean'`)
- [x] 3.9 Implement `classification_path` materialization as an `ltree` of concept permids, consistent with the new `containing_concept_permid`
  - **Follow-on issue found during real-data testing**: `rebuild_taxa()`'s upsert failed with `failed to add item to index page in "taxa_path_idx"` — the same depth-70 chains from 3.7 produce `classification_path` values up to 2,589 characters, too large for a GiST index page. Fixed by dropping the `taxa_path_idx` GiST index on the new `taxa` table only (`taxa_linnaean`'s own GiST index is untouched — its chains stay shallow). The column and its data are unaffected; consumers needing ancestor/descendant queries over the combined hierarchy's deep chains should recurse over `containing_concept_permid` instead.
- [x] 3.10 Implement `rebuild_taxa()`: `derive_taxa(all)` → upsert into `taxa` in place, plus the invariant-check helper (`derive_taxa(all) ≡ current taxa rows`)
- [x] 3.11 Confirm `derive_taxa()` never raises on a containment cycle — verified against the full real dataset: 53 genuine cycles were found and cut across the merged graph (including the cross-boundary Eukarya/Proepitheliozoa/Euradiculata case), none raised; `derive_taxa(NULL)` returned 515,489 rows in ~729s. Performance (~12 min for a full derive) is a real cost of merging the domains, not a correctness problem — flagged to the user as worth a decision on whether it's acceptable as-is or warrants further optimization (e.g. avoiding a full `_dtu_assign`/`_dtu_node` rebuild every cut iteration).
